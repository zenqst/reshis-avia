# Решись Авиа

Приложение для кейса турнира «Решись»: Next.js App Router, React, TypeScript и Chart.js. Использует собственный прогноз из `my_forecast.csv` и параметры направлений из `routes.csv`. Данные читаются сервером, прогноз доступен через защищённый API.

## Локальный запуск

Нужен Node.js 20.9 или новее и PostgreSQL в Neon с HTTP SQL endpoint. Реализация базы использует HTTPS-запросы к `https://HOST/sql`; произвольный локальный PostgreSQL с этим адаптером несовместим.

```powershell
npm ci
Copy-Item .env.example .env.local
# Заполнить DATABASE_URL в .env.local строкой подключения Neon.
npm run dev
```

Открыть http://127.0.0.1:3000, зарегистрировать аккаунт. Таблицы пользователей, сессий и ограничений попыток создаются автоматически; у пользователя базы должны быть права CREATE и ALTER. Секреты не включать в репозиторий.

## Функции и расчёты

- Пять направлений, даты 1 июня — 1 июля 2026 года; 155 строк прогноза.
- По умолчанию используется медиана q=0,5. Дополнительный выбор q=0,1…0,9 меняет рекомендуемую цену и метрики выбранного сценария. Медианный прогноз при текущей цене всегда указан отдельно.
- Спрос: `max(0, base_demand[q] - b * (price - base_price))`; продажи: `min(seats, demand)`. Выручка и прибыль считаются без округления числа пассажиров; вывод округляется. Прибыль сценария — выручка минус затраты на пассажиров, не математическое ожидание и не полная прибыль с фиксированными затратами рейса.
- Оптимальная цена выбирается по максимальной прибыли среди границ разрешённого диапазона, вершины параболы `(cost + base_price + base_demand / b) / 2` и цены полного заполнения `base_price + (base_demand - seats) / b`. Для линейного спроса эти кандидаты покрывают максимум.
- «Колокол» — гауссовская аппроксимация с центром в выбранном спросе и sigma=(q90−q10)/2,56 при базовой цене. Для нулевого разброса используется технический минимум 0,5 пассажира. Ось Y показывает относительную плотность с пиком 100%, а не вероятность. Область отрицательного спроса не показывается.
- «Квантили прогноза» показывает все девять исходных квантилей, сдвинутых по введённой цене и ограниченных снизу нулём. Между уровнями 10% вероятности; хвосты за q10–q90 не восстанавливаются. Совпадающие значения допустимы.
- Регистрация, вход и выход; scrypt-хеши паролей, HttpOnly cookies, срок сессии 12 часов и 30 минут неактивности, ограничения попыток входа.

## Проверки

```powershell
npm run typecheck
npm test
npm run build
npm start
```

`test:prediction` проверяет все квантили на разных вместимостях, нулевой спрос, вырожденный разброс и оптимальность цены относительно перебора. `test:security` проверяет хеширование паролей, JSON, origin и ограничения авторизации с подменённой базой. Эти проверки не заменяют интеграционную проверку с настоящей Neon.

## Размещение

Подходит Node.js-хостинг с поддержкой Next.js (например, Vercel). Корень проекта — `avia`, команда установки `npm ci`, сборки `npm run build`. Задать `DATABASE_URL` в окружении хостинга. В production необходим HTTPS: cookie сессии использует Secure и префикс __Host-. CSV включаются в серверный пакет через outputFileTracingIncludes. Статический экспорт без сервера не поддерживается.

После размещения проверить регистрацию нового пользователя, вход, выход, смену маршрута и даты, оба графика, ручную цену, выбор квантиля, мобильный экран и доступ без авторизации. Не публиковать тестовые пароли и строку подключения.

## Структура и инструменты

`app/` — страницы и API; `src/pages/dashboard` — экран; `src/widgets` — график и блоки интерфейса; `src/features` — авторизация и выбор параметров; `src/entities` — расчёты, данные и сессии; `src/shared` — база, обработка запросов и UI. Шрифты и логотип локальные.

В доработке расчётов, интерфейса, проверок и документации использован OpenAI Codex. Точное название модели и перечень других инструментов первоначальной разработки автору следует указать по фактической истории работы.
